## Accounts and playing together

Accounts/profile data survive clean server restarts when the same persistent data directory is retained. A login on another browser/device uses the same account only when connected to the same backend. **Current policy permits one active login per account:** a new login logs the previous session out. Separate players must use separate accounts to play simultaneously.

There is no "saved forever" guarantee. Use persistent storage, private backups and tested restores. Email is unverified; self-service password recovery is not implemented. Do not lose the game password.

Different-house play needs a running public server, reachable routing/firewall configuration and suitable HTTPS/WSS. Public hosting, actual remote-house play and region infrastructure were not provisioned or validated. Redis, PostgreSQL, global matchmaking, seven-region selection, failover and container-based regional deployment are still proposals, not features in this ZIP.

## Safe startup

Node.js 20+. Extract into a new folder, enter `hamu-master`, run `npm ci`, then `npm start`. Read the actual printed server port. Do not overwrite an existing installation/data directory with this archive.

For isolated validation, create a fresh `HAMU_DATA_DIR` per run. Start the exported server factory with `migrateLegacy:false` for account-free smoke tests; normal startup can migrate project `data/` if present. Never use original saves or bundled admin credentials for testing. Never run multiple server processes against the same JSON account directory.

**PRIVATE:** original account-related material/launcher credential content is intentionally retained unchanged. Do not publish this ZIP. No temporary test accounts, node_modules, caches or browser profiles are included. A separate release/privacy/security pass is required.
